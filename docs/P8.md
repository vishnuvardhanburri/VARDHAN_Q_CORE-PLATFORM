# P8: Adversarial System-Level Attack Campaign

**Baseline:** `git tag vP7.3-frozen`  
**Principle:** P8 attacks the frozen P7.3 baseline. P8 does not redesign P7.3.  
Any discovered defect must be reproduced against the frozen baseline, fixed in a
new revision, covered by a regression test, and assigned a new evidence tag.

---

## Operating Rule

> **P8 attacks the `vP7.3-frozen` baseline. P8 does not redesign P7.3. Any
> discovered defect must be reproduced against the frozen baseline, fixed in a
> new revision, covered by a regression test, and assigned a new evidence
> revision.**

Standard Raft assumes **fail-stop** (non-Byzantine) failures. It preserves
safety under message delays, partitions, loss, duplication, and reordering,
but **not** under a server that intentionally lies or sends conflicting
protocol messages. ([Raft][1])

This document records P8's systematic attack on the Vardhan evidence chain
to discover defects **beyond** what P7.3's fail-stop adversarial testing
covered.

---

## Security Invariants (I1–I10)

P8 is measured by whether the system preserves these invariants under
hostile conditions — **not** by test count.

| ID | Invariant |
|----|-----------|
| I1 | No unauthorized or stale write reaches upstream |
| I2 | No two valid leaders simultaneously authorize writes at the same log index |
| I3 | No committed state-machine command is applied differently across replicas |
| I4 | No authenticated transport accepts altered, replayed, or downgraded ciphertext |
| I5 | Replay of a valid frame cannot produce a second valid state transition |
| I6 | Corruption of persisted evidence cannot silently become valid evidence |
| I7 | Committed evidence survives permitted crash/recovery scenarios |
| I8 | Key compromise or rotation does not silently preserve unauthorized access |
| I9 | Resource exhaustion cannot bypass security boundaries |
| I10 | Evidence remains independently verifiable after failure scenarios |

## P8 Attack Campaign

### P8.1: Byzantine Node Injection
**Attack:** A node sends conflicting `RequestVote` responses (votes for two
candidates in the same term), sends `AppendEntries` with fabricated log
entries, or claims a higher term without justification.

**Invariants targeted:** I2, I3, I5

**Result:**
- ✅ **I5 (one vote per term):** Raft correctly grants at most one vote per term. Double votes and vote replays are rejected.
- ✅ **I2 (no stale leader):** Stale-term AppendEntries (term < current) are rejected.
- ✅ **I3 (committed entry protection):** Wrong `prev_log_term` entries are rejected by log matching.
- ⚠️ **P8-001 Finding:** Committed entries CAN be truncated by a same-term Byzantine leader at the Raft layer. `log.truncate(prev_idx)` at `raft.rs:622` does not check `commit_index`. This is **transport-layer mitigated** — only ML-KEM/ML-DSA authenticated nodes can establish AEAD connections. However, this is not equivalent to state-machine enforcement; a compromised authenticated peer can still truncate committed entries. **Recommendation:** Add `commit_index` check before `truncate()` in the next revision.
- ⚠️ **P8-002 Finding (documented):** A Byzantine leader can create log forks (divergent entries at the same index) on followers. **Crash-stop Raft safety remains validated; Byzantine behavior is outside the base Raft fault model** and requires explicit detection/fencing mechanisms. Quorum intersection protects committed state under fail-stop assumptions, but a malicious authenticated node can still send inconsistent information to different peers.

**Tests:** `raft_p8_byzantine` — 8/8 passing (P8.1a, P8.1b, P8.1c, P8.1d, P8.1e, P8.1f, P8.1g, P8-001)

**Status:** P8.1 COMPLETE — 8/8 tests passing, 2 findings documented (P8-001, P8-002)

### P8.2: Protocol Fuzzing
**Attack:** Malformed AEAD ciphertext frames; corrupted parser input; oversized
payloads; partial/truncated frames; invalid frame size headers.

**Invariants targeted:** I4, I5, I9

**Result:**
- ✅ **I9 (no crashes):** Oversized length headers, truncated ciphertext, and corrupt
  ciphertext are all rejected without panicking. (`ProxyError::FrameTooLarge`, timeouts)
- ✅ **I4 (no altered ciphertext):** Corrupted AES-256-GCM ciphertext fails authentication.
- ✅ **I5 (replay prevention):** Valid frames still work correctly after all fuzz cases.
- ✅ **I9 (zero-length edge case):** Zero-length frames are handled gracefully.

**Tests:** `raft_p8_transport` — 5/5 passing (P8.2a–P8.2e)

**Status:** P8.2 COMPLETE — no vulnerabilities found, all malformed inputs rejected

### P8.3: AEAD Replay / Downgrade Attacks
**Attack:** Capture and replay valid AEAD frames; attempt protocol version
downgrade; reuse nonces.

**Invariants targeted:** I4, I5

**Result:**
- ✅ **I4 (no altered ciphertext):** Corrupted ciphertext is rejected with `CryptoError` (AES-256-GCM authentication tag fails).
- ✅ **I5 (replay prevention):** AEAD nonce sequencing + AAD binding (session_id || direction || seq || version || length) prevents replay with old nonces. Raft-level replay is idempotent (same entry doesn't create duplicate log entries).
- ✅ **I4 (version downgrade):** Only protocol version 1 is accepted; versions 0 and 2 are rejected. Direction byte in AAD prevents cross-direction replay.

**Tests:** `raft_p8_transport` — 9/9 passing (P8.2a–P8.2e + P8.3a–P8.3d)

**Status:** P8.3 COMPLETE — no vulnerabilities found, all replay/downgrade attempts rejected

### P8.4: Network Partition + Concurrent Election + Write
**Attack:** Isolate the leader, force concurrent elections in both partitions,
attempt writes on both sides.

**Invariants targeted:** I1, I2, I3

**Result:**
- ✅ **I2 (no split-brain):** At most 1 leader exists at any time, even under partition. Quorum intersection prevents two concurrent leaders.
- ✅ **I1 (no unauthorized writes):** Isolated nodes cannot submit entries (not leader) or commit without quorum.
- ✅ **I3 (state convergence):** After partition heals, all nodes converge to identical logs via AppendEntries catch-up (truncate + append).
- ✅ **I2 (minority election prevention):** A 1-node minority partition cannot elect a leader (needs ≥2 votes out of 3).

**Tests:** `raft_p8_partition` — 3/3 passing (P8.4a, P8.4b, P8.4c)

**Status:** P8.4 COMPLETE — no vulnerabilities found, no split-brain under partition

### P8.5: Crash During Persistence
**Attack:** Kill nodes at precise moments during checkpoint writes, ledger
appends, and state snapshots. Restart and verify recovery.

**Invariants targeted:** I6, I9

**Result:**
- ✅ **I6 (crash safety):** Torn writes are handled safely:
  - Torn Raft state file → `load_persistent_state` fails to parse → node starts fresh (term=0)
  - Torn ledger write → `scan_existing_ledger` truncates to last valid byte boundary
  - Torn checkpoint file → `scan_existing_checkpoints` returns JSON parse error
- ✅ **I9 (no crash):** Corrupted/invalid JSON doesn't crash the process
- ✅ **Atomic writes:** `persist_state_with` uses write-to-temp + rename pattern

**Tests:** `raft_p8_crash_corruption` — 3/3 passing (P8.5a, P8.5b, P8.5c)

**Status:** P8.5 COMPLETE — all crash-during-persistence scenarios handled safely

### P8.6: Storage Corruption
**Attack:** Corrupt `ledger.jsonl`, `checkpoints.jsonl`, and `raft_state.json`
files. Run verification and recovery.

**Invariants targeted:** I6, I7

**Result:**
- ✅ **I7 (ledger integrity):** Corrupted ledger entries (tampered event data) are detected via hash chain break (prev_hash mismatch) during `LedgerWriter::open`
- ✅ **I7 (checkpoint signature):** Checkpoints with forged signatures (wrong key) fail ML-DSA-87 verification
- ✅ **I7 (checkpoint chain):** Corrupted `previous_checkpoint_hash` is detected by `CheckpointWriter::open` during chain scanning
- ✅ **I7 (Merkle root):** Tampered ledger entries produce different Merkle root, mismatch with stored checkpoint
- ✅ **I9 (no crash):** Corrupted Raft state → node starts fresh without crashing

**Tests:** `raft_p8_crash_corruption` — 7/7 passing (P8.6a–P8.6g)

**Status:** P8.6 COMPLETE — all storage corruption scenarios detected

### P8.7: Key Compromise / Rotation / Revocation
**Attack:** Forge ledger entries and checkpoints using a compromised signing key;
switch signing keys mid-ledger; attempt to tamper with signer fingerprints.

**Invariants targeted:** I7, I10

**Result:**
- ✅ **I7 (key substitution):** Signatures forged with an attacker's key fail ML-DSA-87 verification against the legitimate public key
- ✅ **I7 (key switch detection):** Signer fingerprints differ when keys are switched (detectable via inspection)
- ✅ **I7 (forged checkpoint):** Checkpoint signed with attacker's key fails signature verification
- ✅ **I7 (Merkle root integrity):** Tampered ledger produces different Merkle root, mismatch with checkpoint
- ⚠️ **P8-003 Finding (documented):** No signing key rotation mechanism. `rotate_key_protector` only re-wraps the key at rest — it does NOT generate a new ML-DSA-87 signing key. If the signing key is compromised, there is no API to rotate it. Session/API key revocation exists via `SessionStore::revoke_by_id`, but signing key revocation does not.
- ⚠️ **P8-004 Finding (PENDING FIX):** `Checkpoint::canonical_bytes()` does NOT include `signer_pub_fingerprint` in the signed data. Changing the fingerprint does NOT invalidate the signature. `pq_verify` catches this via a *separate* fingerprint comparison, but the signature itself does not cryptographically bind the identity. Fix: include `signer_pub_fingerprint` in `canonical_bytes()`.

**Tests:** `raft_p8_key_compromise` — 6/6 passing (P8.7a–P8.7f)

### P8.8: Resource Exhaustion
**Attack:** Exhaust disk space during checkpoint writes; exhaust memory with
oversized messages; saturate network bandwidth; attempt nonce exhaustion.

**Invariants targeted:** I8, I9

**Result:**
- ✅ **I9 (no crashes):** Oversized frames (4 bytes over limit) are rejected by `write_frame` with `FrameTooLarge`. Oversized length headers received by `read_frame` are rejected before allocating.
- ✅ **I8 (bounded buffer):** `read_buf` has capacity `MAX_FRAME_SIZE * 2` and rejects frames > `MAX_FRAME_SIZE + 16`. 100 concurrent frames processed without buffer leak.
- ✅ **I8 (valid boundary):** Frames at exactly `MAX_FRAME_SIZE` (256KB) are accepted. Frames at `MAX_FRAME_SIZE + 16` (boundary with GCM tag) are rejected.
- ✅ **I8 (nonce space):** Nonce uses `u64` sequence number → 2^64 frames possible (≈4.3M exabytes) — practically inexhaustible.
- ⚠️ **P8-005 Finding (documented):** Ledger has no size cap. Unbounded append-only growth at ~9.5KB/entry (due to ML-DSA-87 signatures) can exhaust disk. Requires operational log rotation.

**Tests:** `raft_p8_resource_exhaustion` — 7/7 passing (P8.8a–P8.8g)

**Status:** P8.8 COMPLETE — 1 finding documented (P8-005: unbounded ledger growth)

### P8.9: Long-Duration Distributed Soak
**Attack:** Run a 3-node TCP cluster for 5+ seconds under continuous failure
injection (crash + restart) with continuous writes, verifying safety
invariants (I2, I3) throughout.

**Invariants targeted:** I1, I2, I3

**Result:**
- ✅ **I2 (no split-brain):** At most 1 leader exists at any time during the entire soak, even with continuous crash/restart of nodes.
- ✅ **I3 (consistency):** Committed entries remain consistent across all active nodes. Logs converge after node restart via AppendEntries catch-up.
- ✅ **I1 (no unauthorized writes):** Entries are only accepted by the legitimate leader (quorum required for commit).
- ✅ **Liveness:** Cluster recovers with a new leader after all injected failures.

**Tests:** `raft_p8_soak` — 1/1 passing (P8.9a)

**Status:** P8.9 COMPLETE — cluster maintains safety under continuous failure injection
