# VARDHAN INTEGRATION MILESTONE — CANONICAL INTELLIGENCE → Q-CORE CONTRACT

## 1. Architectural Boundary Principles

The boundary between **Vardhan Intelligence** (the Node.js/TypeScript observation and discovery plane) and **Vardhan Q-Core** (the Rust cryptographic and policy enforcement substrate) is strictly unidirectional in trust:

1. **Intelligence Discovers, Q-Core Verifies**: The Intelligence plane is responsible for semantics, heuristics, differential analysis, and evidence gathering. Q-Core is entirely agnostic to *how* a finding was discovered. It only verifies structural integrity, tenant isolation, provenance, and policy.
2. **No Implicit Trust**: A finding generated by Intelligence is untrusted until Q-Core processes it. Merely passing a payload to Q-Core does not verify it.
3. **No Automatic Destructive Action**: Intelligence proposes a `DecisionCandidate`. Q-Core evaluates the action against the Tenant Policy and Authority Gate. If authorized, it is sealed. No real-world destructive execution occurs without cryptographic authorization.
4. **Stable Canonical Contract**: Communication occurs via a stable JSON schema over IPC (Standard I/O) between the Node.js process and the compiled Rust binary.

## 2. Request/Response Contract

### Q-Core Request Schema (Finding Payload)

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "QCoreValidationRequest",
  "type": "object",
  "required": ["tenant_id", "finding_id", "evidence_package", "decision_candidate", "provenance"],
  "properties": {
    "tenant_id": { "type": "string", "format": "uuid" },
    "finding_id": { "type": "string", "format": "uuid" },
    "evidence_package": {
      "type": "object",
      "required": ["evidence_id", "data_hash", "category"],
      "properties": {
        "evidence_id": { "type": "string", "format": "uuid" },
        "data_hash": { "type": "string" },
        "category": { "type": "string" }
      }
    },
    "decision_candidate": {
      "type": "object",
      "required": ["action_type", "policy_reference"],
      "properties": {
        "action_type": { "type": "string" },
        "policy_reference": { "type": "string" }
      }
    },
    "provenance": {
      "type": "object",
      "required": ["source_identity", "timestamp", "version"],
      "properties": {
        "source_identity": { "type": "string" },
        "timestamp": { "type": "string", "format": "date-time" },
        "version": { "type": "string" }
      }
    }
  }
}
```

### Q-Core Response Schema (Canonical Receipt)

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "QCoreReceipt",
  "type": "object",
  "required": ["receipt_id", "status", "tenant_id", "finding_id", "ledger_commit_index", "signatures"],
  "properties": {
    "receipt_id": { "type": "string" },
    "status": { "type": "string", "enum": ["SEALED", "REJECTED_UNAUTHORIZED", "REJECTED_MALFORMED", "REJECTED_PROVENANCE"] },
    "tenant_id": { "type": "string", "format": "uuid" },
    "finding_id": { "type": "string", "format": "uuid" },
    "ledger_commit_index": { "type": "integer" },
    "signatures": {
      "type": "object",
      "properties": {
        "ed25519": { "type": "string" },
        "ml_dsa_87": { "type": "string" }
      }
    },
    "error_details": { "type": "string" }
  }
}
```

## 3. Interaction Flow
1. **Vardhan Intelligence** constructs the `QCoreValidationRequest` and serializes it to JSON.
2. It spawns the `vardhan-receipt` binary, passing the JSON via STDIN.
3. **Q-Core** deserializes the payload.
4. **Q-Core Validations**:
   - Schema structural integrity.
   - Tenant matching (ensure the current execution context matches `tenant_id`).
   - Provenance timestamp is not in the future or drastically stale (replay prevention).
   - Identity has permission to propose `action_type`.
5. **Q-Core Execution**:
   - Constructs a Canonical Evidence Record.
   - Computes state hash.
   - Signs with Ed25519 and ML-DSA-87.
   - Outputs the `QCoreReceipt` JSON to STDOUT.
6. **Vardhan Intelligence** parses STDOUT and records the receipt.
