### 4.1 Timeline

|-------|-----------------|
| Kill command issued | 2026-09-09T17:43:25.3NZ |
| Node A (us-east-1) detected as Dead | 2026-09-09T17:43:31.3NZ |

| Node A restart initiated | 2026-09-09T17:43:36.3NZ |
| Node A rejoined as healthy | 2026-09-09T17:43:38.3NZ |
| **Recovery time** | **2,089 ms** |

### 4.2 Failover breakdown

- t+0s: us-east-1 region killed (both Node A and Node B terminated)
- t+1s–t+4s: us-east-1 nodes still appear healthy in eu-west-1's view
  (heartbeat send loop continues to tick; seed entries have not yet aged out)
- t+5s: heartbeat timeout fires (5000ms threshold). All us-east-1 nodes
  reaped as Dead. `peer_snapshot()` filters them out. eu-west-1 has 2 healthy nodes.
- **Failover detection: 5,558ms** (5s timeout + ~558ms tick alignment)

> The 5.5s detection latency is a consequence of `dead_threshold_ms = 5000`
> and `tick_interval_ms = 1000`. The first tick after timeout fires at
> t+5s, plus up to ~1s for tick alignment = worst case ~6s. In production
> with lower tick intervals (e.g., 200ms), this would drop to ~5.2s.

## 10. Bug Fixes During P3.5 Validation

Three defects were identified and fixed during local validation (all in `ha_cluster`):

### 10.1 Heartbeat send loop — 0.0.0.0 address substitution
**Symptom:** After initial heartbeat exchange, peer entries carry `addr=0.0.0.0:8082`
(from the node's listen address). Sending UDP to `0.0.0.0` on macOS silently
drops packets.

**Fix:** `heartbeat.rs` send loop now checks `peer.addr.ip()` and substitutes
`127.0.0.1` when the IP is unspecified (`0.0.0.0`).

### 10.2 Heartbeat mesh — always send to all healthy peers
**Symptom:** Region-aware send loop sent only to same-region peers. After
the first heartbeat exchange, only same-region entries existed — cross-region
peers were starved and reaped as Dead after 5s.

**Fix:** Send loop always broadcasts to all `healthy_peers()`. Region preference
is applied to traffic routing, not to the heartbeat mesh.

### 10.3 `apply_heartbeat` — allow Dead → Healthy via heartbeat
**Symptom:** A node killed and restarted (simulating recovery) remained Dead
in peer tables forever, because `apply_heartbeat` explicitly refused to
transition Dead → Healthy.

**Fix:** Allow Dead → Healthy when the heartbeat timestamp is newer (the
`last_seen_ms >= entry.last_seen_ms` check already prevents stale packet
spoofing). `Draining` state is still protected — only cleared via explicit
`mark_healthy()`.

## 14. Limitations & Next Steps

- **Local simulation only**: Latency numbers are localhost, not real cross-region RTT.
  Real AWS deployment (Step 2 of original plan) requires AWS credentials and
  EKS cluster provisioning.

  Production tuning may lower this to 2–3s.
- **CPU profiling**: Process RSS measured (~18.5MB avg). Detailed `perf`/`pprof`
  profiling recommended for production sizing.
