# P1/P2 Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Close the remaining P1 security/integration evidence and make the seven Phase 2 industry planes runtime-authoritative, while preserving the green CI baseline.

**Architecture:** Keep existing control-plane identity, receipt, SDK, and enterprise-tenant boundaries intact. Add focused contract/adversarial tests at the existing trust boundaries and load the seven checked-in industry plane contracts through a typed runtime registry so the JSON contracts are executable configuration rather than documentation-only artifacts.

**Tech Stack:** Rust, Axum, serde/serde_json, existing control-plane test harnesses, Python/TypeScript/Go/Rust SDK contracts, GitHub Actions.

**Spec:** Existing VARDHAN_Q_CORE P1 completion gate and Phase 2 industry-plane requirements documented in `docs/P1_SECURITY_READINESS_EVIDENCE.md`, `docs/P1_THREAT_MODEL.md`, `docs/P1_RECEIPT_TRUST_MODEL.md`, and the seven `industries/*/plane.json` contracts.

## Global Constraints

- Direct `main` execution is authorized; do not create a feature branch or PR.
- Preserve fail-closed tenant isolation and server-authoritative RBAC.
- Do not weaken cryptographic verification or replace production behavior with test-only bypasses.
- Every security/integration change must have a focused regression test.
- Green CI is necessary but not sufficient; each P1/P2 requirement must have direct evidence.

## Review Focus

- Cross-tenant identity projection must never become privileged by default — adversarial role tests.
- SAML/OIDC/WebAuthn/SCIM boundaries must reject malformed, replayed, expired, or cross-tenant assertions — negative tests.
- Receipt publication must remain authenticated and tenant-bound from the canonical sealing path — producer/transport integration evidence.
- SDK resources must expose consistent idempotency and webhook verification behavior — generated inventory/contract checks.
- Industry JSON must be consumed by runtime code and remain schema-valid — typed registry tests.
