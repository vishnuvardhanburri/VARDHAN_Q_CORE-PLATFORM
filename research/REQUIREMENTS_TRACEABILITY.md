## Limitations (apply to every row)

- **Single-node only.** G1 packet §1: multi-node/multi-region/zero-downtime, RAFT (`ha_cluster`, EXPERIMENTAL) out of scope; G2/G3 close single-node only.
- **Dev-Vault ≠ HSM.** G4 drill uses a dev Vault transit engine (`vault server -dev`, owner-provisioned binary); prod Vault cluster + HSM are owner-provisioned, never part of this lab.
- **Policy evaluation is embedded, not a standalone engine.** `grep -ri "policy" backend/*/src` returns hits in many crates (535 lines at HEAD), but all are embedded checks — e.g. `GatewayAuthorityEvaluator::evaluate` + `TenantRegistry::is_known`/`DENY_TENANT_UNKNOWN` in `backend/vardhan_receipt/src/policy_authority.rs`, `PolicyEvaluation`/`PolicyStatus` types in `backend/vardhan_state/src/authorization.rs` consumed by `backend/authority_gate`, MFA/password/retention policies in `auth_service`/`audit_ledger`. There is no standalone policy engine (no OPA/Cedar/Rego-style service); authorization logic lives in application code and fails closed (empty config → deny-all). Honest status: embedded fail-closed evaluation, not an externalized policy plane.
